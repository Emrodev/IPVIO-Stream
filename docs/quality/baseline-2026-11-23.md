## 6. How to repeat the local run

From the repository root, with ktlint, detekt-cli and mobsfscan (plus semgrep) installed:

    ktlint "app/src/**/*.kt" --reporter=plain
    java -jar detekt-cli.jar --input app/src/main/java --report txt:detekt.txt
    mobsfscan --json -o mobsf.json app/src/main

OSV-Scanner needs a lockfile first (Gradle dependency locking), then `osv-scanner scan source -r .`.

## 8. Gradle lockfile for OSV-Scanner (steps for the maintainer)

Not done in this environment: Google Maven is not reachable from the sandbox and Maven Central returns 429, so Gradle cannot resolve the dependencies and write the locks here. `app/build.gradle.kts` is unchanged.

1. In `app/build.gradle.kts` add a locking block (Gradle 9 syntax, **to verify in Android Studio**): `dependencyLocking { lockAllConfigurations() }` at project level.
2. Run `./gradlew assembleDebug --write-locks` once. This writes `gradle.lockfile` files for all configurations.
3. Commit the lock files. Build behaviour does not change while the locks match.
4. Then `osv-scanner scan source -r .` reads the lockfiles. It needs network access to api.osv.dev, which the sandbox does not have. Run it on the maintainer's machine or in CI.

Changing the build file and adding CI steps need approval (CLAUDE.md, sections 6 and 12).
